# Contributing to DiveChecker

**English** | [한국어](docs/CONTRIBUTING.ko.md)

Thank you for your interest in contributing to DiveChecker! This guide will help you get started.

## Prerequisites

- Flutter SDK 3.10.4+ / Dart 3.10+
- Pico SDK 2.2.0 (firmware only)
- CMake 3.13+ (firmware only)
- Android Studio / Xcode (mobile builds only)
- Python 3.9+ (website verification scripts only)

## Build

### App

```bash
git clone https://github.com/kernalix7/DiveChecker.git
cd DiveChecker/_0_DiveChecker-APP
flutter pub get
flutter gen-l10n
flutter run
```

### Firmware

```bash
cd 0_Pico2-Firmware/Divechecker
mkdir -p build && cd build
cmake .. && make -j$(nproc)
# Output: Divechecker.uf2 — drag-and-drop to Pico2 BOOTSEL
```

### Website (static)

```bash
python3 -m http.server -d website 8000
# → http://localhost:8000
```

## Test

```bash
# App
cd _0_DiveChecker-APP
flutter test
flutter analyze --no-fatal-infos

# Website (HTML parser + i18n keys resolve)
python3 -c "import html.parser; [html.parser.HTMLParser().feed(open(f).read()) for f in ['website/index.html','website/vent.html','website/faq.html','website/support.html','website/disclaimer.html','website/privacy.html']]"
```

## Workflow

1. **Fork** the repository
2. Create a **feature branch** (`git checkout -b feat/my-feature`)
3. Write your changes following **conventional commits**
4. Submit a **Pull Request**

## PR Checklist

Before submitting a PR, ensure the following:

- [ ] `flutter test` passes
- [ ] `flutter analyze --no-fatal-infos` reports zero errors
- [ ] Firmware changes built (`cmake .. && make -j$(nproc)`) and flashed for smoke test
- [ ] Website changes: HTML parses, i18n keys resolve, no Korean baked into EN HTML defaults
- [ ] Documentation is updated (CHANGELOG + docs/*.ko.md mirror when EN changes)
- [ ] No hardcoded credentials or secrets
- [ ] No AI attribution (`Co-Authored-By`, `Generated by`, etc.) in commits or PR body

## Commit Convention

Use [Conventional Commits](https://www.conventionalcommits.org/):

| Prefix | Use for |
|--------|---------|
| `feat` | New feature |
| `fix` | Bug fix |
| `refactor` | Internal change, no behavior shift |
| `docs` | Documentation only |
| `test` | Test changes only |
| `chore` | Build / tooling / CI |
| `ci` | CI workflow changes |

Scope: `feat(app):`, `feat(firmware):`, `feat(website):`, `fix(cad):`, etc.
